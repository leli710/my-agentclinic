# מפרט פיצ'ר — Hello Hono

**סטטוס:** המימוש קיים; המפרט המובנה נבדק מחדש ב־2026-11-14<br>
**מפרטי הדרישות, התוכנית והאימות:** `specs/2026-11-14-hello-hono/`<br>
**מטרה:** להוסיף שרת Hono מקומי מינימלי, כדי לאמת את תשתית השרת בלי להקדים את פיצ'ר Agents and Ailments.

## 1. רקע והיקף

הפיצ'ר מאמת שרת Hono מקומי ומספק את חוזה הדוגמה `GET /api/hello`. הוא כולל גם Layout משותף בעברית עם רכיבי Header, Main ו־Footer נפרדים, CSS מקומי ותמיכה רספונסיבית. דף הבית מציג כיום את Dashboard המוצר; חוזה הברכה נשאר בנתיב ה־API ואינו מוחלף בדף.

## 2. מחוץ להיקף

- נתוני סוכנים ותקלות, SQLite, SQL migrations או טפסי CRUD.
- התחברות, משתמשים, APIs חיצוניים, קריאות AI או פעולות רשת יוצאות.
- הגדרת Dashboard או תוכן מוצר מעבר לתגובה המוגדרת להלן.

## 3. דרישות פונקציונליות

| מזהה | דרישה |
|---|---|
| FR-1 | בקשת `GET /api/hello` תחזיר סטטוס `200`. |
| FR-2 | גוף התשובה יהיה JSON מדויק בצורה `{"message":"Hello Hono!"}`. |
| FR-3 | כותרת התוכן תציין `application/json`. |
| FR-4 | נתיבים ושיטות HTTP שלא הוגדרו לא יטופלו כאילו הצליחו; ישמרו התנהגות 404/405 התקנית של Hono. |
| FR-5 | השרת יאזין מקומית בלבד ב־`127.0.0.1:3000`, ולא ייחשף לרשת החיצונית. |
| FR-6 | אם השרת אינו יכול לעלות, השגיאה תוצג באופן גלוי; אין מעבר שקט לפורט או לממשק חלופי. |
| FR-7 | כל דף HTML ישתמש ב־Layout משותף עם Header, Main ו־Footer סמנטיים. |
| FR-8 | Header, Main ו־Footer ימומשו ברכיבים נפרדים, כל אחד בקובץ משלו. |
| FR-9 | ה־Layout יגדיר `lang="he"` ו־`dir="rtl"` ויטען CSS מקומי, ללא CDN. |
| FR-10 | הפריסה תישאר שמישה ברוחבים צרים ולא תגרום לגלילה אופקית של כל העמוד. |

## 4. דרישות טכניות

- סביבת ריצה: Node.js ‏`25.2.1` שנמצאה בסביבת העבודה; מתאם Hono תומך ב־Node.js ‏20 ומעלה.
- TypeScript ‏`5.9.3` הקיים יישמר ב־Strict Mode; לא משדרגים אותו ללא צורך.
- גרסאות ישירות מדויקות, שאומתו מול רישום npm ב־12.11.2026:
  - `hono` ‏`4.13.18`
  - `@hono/node-server` ‏`2.1.8`
  - `@types/node` ‏`25.9.9`
  - `typescript` ‏`5.9.3`
- לשמור את הגרסאות המדויקות גם ב־`package.json` וגם ב־`package-lock.json`; התקנות שחזור יתבצעו באמצעות `npm ci`.
- להשתמש ב־ES Modules וב־`NodeNext`, ולייצא יצירת אפליקציית Hono בנפרד מקוד פתיחת השרת כדי לאפשר בדיקה ללא פתיחת פורט.
- להשתמש ב־Vitest להרצת בדיקות TypeScript ולשמור על `npm test` כפקודת Build ובדיקה.
- לשמור את רכיבי התצוגה המשותפים ב־`src/views/header.ts`,‏ `src/views/main.ts` ו־`src/views/footer.ts`; להרכיב אותם ב־`src/views/layout.ts`.
- לשמור את כל ה־CSS ב־`public/styles.css` ולהתאים את הפריסה למסכים צרים.
- השרת ייקשר ל־loopback (`127.0.0.1`) בפורט `3000`.
- אין להוסיף SQLite או Pico CSS בפיצ'ר הזה.
- אין לטעון CDN, ליצור חיבורי רשת יוצאים או לשלוח טלמטריה.

## 5. תוכנית עבודה וקבוצות משימות

### קבוצה א — תלויות וקומפילציה

1. להפוך את גרסת TypeScript הקיימת לתלות מדויקת.
2. להוסיף את `hono` ואת `@hono/node-server` כגרסאות מדויקות.
3. להוסיף `@types/node` בגרסה מדויקת ולהגדיר טיפוסי Node בקומפילציה.
4. לבדוק את `package-lock.json` ואת `npm ci` בלי לעדכן תלויות לא קשורות.

### קבוצה ב — אפליקציית Hono

1. ליצור מודול אפליקציה שמייצא מופע Hono.
2. להגדיר `GET /api/hello` עם חוזה התגובה של FR-1 עד FR-3. נתיב השורש מציג את דף הבית של המוצר.
3. לשמור על תגובות Hono התקניות לנתיבים ולשיטות שלא הוגדרו.

### קבוצה ג — שרת מקומי

1. להוסיף entry point שמפעיל את מתאם Node.
2. להאזין ב־`127.0.0.1:3000`.
3. להוסיף סקריפט הרצה ברור ב־`package.json`.
4. לוודא ששגיאת הפעלה אינה נבלעת.

### קבוצה ד — Layout ועיצוב

1. ליצור רכיבי Header, Main ו־Footer נפרדים ולהרכיב אותם ב־Layout.
2. לקשר CSS מקומי ולבדוק RTL, HTML סמנטי וגלישה ברוחבים צרים.

### קבוצה ה — אימות ותיעוד

1. להריץ TypeScript Build ו־Vitest.
2. להפעיל את השרת בפקודת הפרויקט.
3. לבדוק בפועל `GET http://127.0.0.1:3000/api/hello`, את הסטטוס, ה־JSON וה־Content-Type.
4. לבדוק נתיב לא קיים ולוודא שאינו מחזיר תגובת הצלחה.
5. לעדכן את README ואת `TASKS.md` בתוצאות המאומתות.
