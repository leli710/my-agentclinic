# טכנולוגיות וכללי פיתוח — Agent Clinic

## סביבת העבודה

- **Node.js:** סביבת הריצה של השרת.
- **גרסת מינימום:** Node.js ‏22.12, בהתאם לדרישת Vitest ‏4.1.2; הסביבה הנוכחית היא ‏25.2.1.
- **npm:** ניהול תלויות, עם `package-lock.json` מחויב למאגר ושימוש ב־`npm ci` לשחזור ההתקנה.
- **TypeScript:** שפת היישום, עם `strict: true`, טיפוסים מפורשים בגבולות API וקלט, וקומפילציה ללא פליטת קוד במקרה של שגיאה.
- **בדיקות:** Vitest להרצת בדיקות TypeScript באמצעות `npm test`; בדיקות HTTP משתמשות ב־Hono `app.request` ומסד נתונים בזיכרון.
- **שפת עיצוב:** כתום ושחור כצבעי מותג, עם צבעי מצב נפרדים לקריאות.
- **Git:** עבודה בענפים מקומיים נפרדים לפיצ'רים; אין Push או Merge ללא אישור מפורש.

הגרסאות הישירות הנוכחיות מדויקות ונעולות ב־`package-lock.json`: Hono ‏`4.13.18`, מתאם Node ‏`2.1.8`, TypeScript ‏`5.9.3`, Vitest ‏`4.1.2`,‏ `better-sqlite3` ‏`13.1.1`, טיפוסי SQLite ‏`7.6.13`,‏ Pico CSS ‏`2.1.1` וטיפוסי Node ‏`25.9.9`. דרייבר SQLite נבדק בסביבת Windows ו־Node.js ‏`25.2.1`.

## ארכיטקטורה מתוכננת

- **שרת:** Hono על Node.js, עם מתאם Node רשמי.
- **ממשק:** HTML שנוצר בצד השרת, עברית ו־RTL, עם CSS מקומי. אין צורך ב־SPA או בשירותי צד שלישי עבור ה־MVP.
- **עיצוב:** Pico CSS יוגש מקובצי הפרויקט/התלויות המקומיים, ולא מ־CDN.
- **אחסון:** SQLite מקומי עם קובצי SQL ממוספרים להגירת סכימה.
- **דרייבר SQLite:** `better-sqlite3` בגרסה מדויקת, שנבדק בהצלחה בסביבת Windows ו־Node.js הנוכחית; לא להשתמש ב־SQLite המובנה הניסיוני של Node בפרויקט.
- **הגירת SQLite:** בדיקת גרסאות הגירה לפני החלה, תיעוד כשלים והבטחת סדר הרצה יציב.
- **עיצוב:** Pico CSS בגרסה מדויקת יוגש מקומית מתוך התלות; עיצוב משלים כתום ושחור יישמר ב־`public/styles.css`.
- **בדיקות:** Vitest ו־Hono `app.request`; בדיקות מוצר יכסו מסלולי הצלחה, קלט לא תקין, זרימות נתונים, migrations ושגיאות persistence.
- **בדיקה נקייה:** `npm ci`, אחריו `npm run build` ו־`npm test` חייבים להצליח.
- **בדיקת HTTP:** לבדוק בפועל את השרת ב־`127.0.0.1:3000`, כולל נתיבים לא תקינים וטפסים.
- **רספונסיביות ו־RTL:** להשתמש ב־HTML סמנטי, `dir="rtl"`, CSS מקומי ו־media queries; לא להסתמך על סקריפטים חיצוניים או על גלילה אופקית של כל העמוד.

בבדיקה הראשונית `node:sqlite` של Node ‏25 הציג אזהרת Experimental. לכן נבחר `better-sqlite3` לאחר התקנה מוצלחת ובדיקת שאילתת SQLite מקומית, כדי למנוע תלות ב־API הניסיוני.

## כללי פיתוח

1. המפרט המאושר הוא מקור האמת; אין להוסיף התנהגות מוצר שלא נדרשה.
2. לפתח בחתכים קטנים: מפרט, משימות, מימוש, בדיקה ועדכון תיעוד.
3. להשתמש ב־TypeScript Strict ולשמור על טיפוסי Domain עצמאיים וברורים.
4. לאמת קלט בצד השרת; אין להסתמך על ולידציה בדפדפן בלבד.
5. להציג שגיאות באופן מפורש; אין להסתיר חריגות או להחזיר הצלחה מדומה.
6. להפריד בין נתיבי Hono, לוגיקת מוצר, persistence ותצוגות.
7. לשמור SQL migrations בקובצי מקור ולבדוק התקנה חדשה ושדרוג ממסד קיים בבדיקות.
8. לתמוך בעברית וב־RTL, כולל מצבי שגיאה, טפסים ומסכים צרים.
9. לא לטעון נכסים או לשלוח מידע מחוץ למחשב בזמן ריצת האפליקציה.
10. לנעול תלויות ולבדוק את ה־Diff לפני Commit.
11. לעדכן את `TASKS.md` ואת `specs/roadmap.md` אחרי התקדמות שאומתה.
12. לא לבצע Commit/Push/Merge של שלבי מפרט או פיצ'ר בלי האישור הנדרש.

## מבנה פרויקט מתוכנן

```text
src/
  app.ts        יצירת אפליקציית Hono ונתיבים
  db.ts         חיבור SQLite, migrations וגישה לנתונים
  domain.ts     טיפוסי מוצר
  validation.ts אימות קלט
  course-progress.ts חישוב התקדמות הקורס מתוך TASKS.md
  views.ts      תצוגות HTML של המסכים
  views/        Layout, Header, Main, Footer וטיפוסי Props
  test/         בדיקות אוטומטיות
public/         CSS מקומי
migrations/     קובצי SQL ממוספרים
specs/          Constitution ומפרטי פיצ'רים
```

המבנה מתאר את הקוד הקיים; יש להוסיף קבצים ותיקיות לפי צורך ממשי, ולא ליצור שכבות ריקות מראש.

## תאימות לרשת מסוננת

- אין שימוש ב־CDN, Google Fonts או תמונות/ספריות מרוחקות.
- כל CSS וסקריפט נדרש יוגש מקומית.
- בזמן ריצה האפליקציה ניגשת למסד המקומי בלבד.
- התקנת תלויות ופיתוח עשויים לדרוש גישה לרישום npm; אם הרשת חוסמת זאת, יש לעצור ולתעד את החסימה במקום לעקוף את הסינון.
