# טכנולוגיות וכללי פיתוח — Agent Clinic

## סביבת העבודה

- **Node.js:** סביבת הריצה של השרת.
- **npm:** ניהול תלויות, עם `package-lock.json` מחויב למאגר ושימוש ב־`npm ci` לשחזור ההתקנה.
- **TypeScript:** שפת היישום, עם `strict: true`, טיפוסים מפורשים בגבולות API וקלט, וקומפילציה ללא פליטת קוד במקרה של שגיאה.
- **Git:** עבודה בענפים מקומיים נפרדים לפיצ'רים; אין Push או Merge ללא אישור מפורש.

בשלד הנוכחי TypeScript ‏5.9.3 מותקן כתלות פיתוח. גרסאות Hono, מתאם Node, SQLite ו־Pico CSS יינעלו בקובץ הנעילה בעת הוספתן, לאחר בדיקת תאימות ב־Windows.

## ארכיטקטורה מתוכננת

- **שרת:** Hono על Node.js, עם מתאם Node רשמי.
- **ממשק:** HTML שנוצר בצד השרת, עברית ו־RTL, עם CSS מקומי. אין צורך ב־SPA או בשירותי צד שלישי עבור ה־MVP.
- **עיצוב:** Pico CSS יוגש מקובצי הפרויקט/התלויות המקומיים, ולא מ־CDN.
- **אחסון:** SQLite מקומי עם קובצי SQL ממוספרים להגירת סכימה.
- **הגירת SQLite:** בדיקת גרסאות הגירה לפני החלה, תיעוד כשלים והבטחת סדר הרצה יציב.
- **בדיקות:** מדיניות מפורטת תתווסף בשלב Replanning; בדיקות מוצר יכסו מסלולי הצלחה, קלט לא תקין ושגיאות persistence.

SQLite המובנה של Node ‏25 זמין בסביבה, אך הציג אזהרת Experimental. לכן אין לקבע אותו כפתרון המוצר לפני בדיקת חלופה יציבה ותאימות Windows. בחירת מתאם SQLite תתועד במפרט הפיצ'ר לפני הוספת התלות.

## כללי פיתוח

1. המפרט המאושר הוא מקור האמת; אין להוסיף התנהגות מוצר שלא נדרשה.
2. לפתח בחתכים קטנים: מפרט, משימות, מימוש, בדיקה ועדכון תיעוד.
3. להשתמש ב־TypeScript Strict ולשמור על טיפוסי Domain עצמאיים וברורים.
4. לאמת קלט בצד השרת; אין להסתמך על ולידציה בדפדפן בלבד.
5. להציג שגיאות באופן מפורש; אין להסתיר חריגות או להחזיר הצלחה מדומה.
6. להפריד בין נתיבי Hono, לוגיקת מוצר, persistence ותצוגות.
7. לשמור SQL migrations בקובצי מקור ולבדוק התקנה חדשה ושדרוג ממסד קיים בבדיקות.
8. לתמוך בעברית וב־RTL, כולל מצבי שגיאה, טפסים ומסכים צרים.
9. לא לטעון נכסים או לשלוח מידע מחוץ למחשב בזמן ריצת האפליקציה.
10. לנעול תלויות ולבדוק את ה־Diff לפני Commit.
11. לעדכן את `TASKS.md` ואת `specs/roadmap.md` אחרי התקדמות שאומתה.
12. לא לבצע Commit/Push/Merge של שלבי מפרט או פיצ'ר בלי האישור הנדרש.

## מבנה פרויקט מתוכנן

```text
src/
  app/          יצירת אפליקציית Hono ונתיבים
  domain/       טיפוסים וכללי מוצר
  db/           חיבור SQLite, migrations וגישה לנתונים
  views/        תצוגות HTML
public/         CSS ונכסים מקומיים
migrations/     קובצי SQL ממוספרים
test/           בדיקות אוטומטיות
specs/          Constitution ומפרטי פיצ'רים
```

המבנה הוא יעד הדרגתי. יש ליצור תיקיות רק כשיש בהן קוד ממשי, ולא להוסיף שכבות ריקות מראש.

## תאימות לרשת מסוננת

- אין שימוש ב־CDN, Google Fonts או תמונות/ספריות מרוחקות.
- כל CSS וסקריפט נדרש יוגש מקומית.
- בזמן ריצה האפליקציה ניגשת למסד המקומי בלבד.
- התקנת תלויות ופיתוח עשויים לדרוש גישה לרישום npm; אם הרשת חוסמת זאת, יש לעצור ולתעד את החסימה במקום לעקוף את הסינון.
